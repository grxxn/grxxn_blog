블로그를 만들면서 처음부터 계획했던 것 중 하나가 댓글기능이었습니다. 댓글은 블로그의 기본중에 기본이고 블로그를 방문해주시는 분들과의 소통창구라고 생각합니다.
DB를 이용하게 된다면 익명으로 댓글을 작성할 수 있는 기능으로 기획할 수 있겠지만 이번 블로그는 백엔드없는 오직 프론트를 이용해 개발했기 때문에 Utterances라는 기능을 사용했습니다.
Utterances를 사용하면 github 저장소의 Issue를 통해 댓글을 관리할 수 있습니다.

## ⚙️ Utterances 설치 및 설정
### 🔍 설치하기
github app에서 Utteracnes를 설치할 수 있습니다. ([Utterances 설치페이지](https://github.com/apps/utterances))   

![utterances repository](/images/post_250830/repo_access.png)

Install을 클릭하면 Utteracnes를 사용할 저장소를 선택하는 화면이 나옵니다. 
특정 저장소로 지정할 경우 private 저장소는 불가능하니 블로그 저장소를 private으로 설정해놨다면 댓글을 관리할 저장소를 새로 파면 됩니다.

### 🔍 Repository 설정하기
이제 설정 페이지로 이동합니다. 먼저 Repository 설정입니다.   
연결할 저장소를 설정해줍니다. <CodeBlock>계정명/저장소</CodeBlock>를 작성해주세요.

![utterances repository](/images/post_250830/config_repo.png)


### 🔍 포스트 ↔️ 이슈 매핑 설정하기
다음 설정은 블로그 포스트와 이슈 매핑 설정입니다.   
특정 포스트에 댓글을 달면 그 포스팅에 대한 이슈가 생성됩니다. 그 포스팅과 이슈 제목의 매핑을 어떻게 할지에 대한 설정입니다.

![utterances repository](/images/post_250830/config_mapping.png)

옵션들의 내용은 다음과 같습니다.
- Issue title contains page pathname
  + URL의 경로까지 기준으로 삼으며 쿼리스트링은 무시됩니다.
  + URL을 <CodeBlock>/blog/post?seq=1423</CodeBlock>과 같이 설정했을 경우 <CodeBlock>/blog/post?seq=1423</CodeBlock>와 <CodeBlock>/blog/post?seq=1265</CodeBlock>는 같은 이슈로 매핑되는 문제가 발생합니다.
- Issue title contains page URL
  + 전체 URL (/blog/post?seq=1532)을 고유값으로 사용합니다.
- Issue title contains page title
  + 글의 <CodeBlock>{"<title>"}</CodeBlock> 태그를 기준으로 매핑합니다. 제목이 바뀌면 다른 이슈로 인식될 수 있기 때문에 제목을 자주 수정한다면 추천하지 않습니다.
- Issue title contains page og:title
  + Open Graph 메타 태그의 og:title을 기준으로 매핑합니다. title과 비슷한 문제가 발생하기 때문에 추천하지 않습니다.
- Specific issue number
  + 특정 Issue 번호와 강제로 연결합니다. 수동관리가 필요하기 때문에 잘 사용되지 않습니다.
- Issue title contains specific term
  + 이슈 제목에 특정 단어가 포함돼 있어야만 매칭되게 하는 옵션입니다.

필자의 블로그는 <CodeBlock>/blog/post?seq=SEQ</CodeBlock>형식을 사용해 두번째 옵션인 page URL을 선택했습니다.


### 🔍 라벨 & 테마 설정하기
다음은 issue-label과 Theme 설정입니다.   

![utterances repository](/images/post_250830/config_label.png)

issue-label 옵션은 깃허브에서 이슈를 자동생성할 때 라벨을 자동으로 붙여주는 설정입니다.   
라벨이란 Github Issues에서 이슈를 분류할 때 쓰는 태그입니다. Utterances는 댓글을 달 때 새로운 이슈를 만들면 지정된 라벨을 붙여줍니다. 라벨을 사용하게 되면 나중에 블로그 댓글용 이슈만 필터링하거나 관리하기 쉬워집니다.

저는 <CodeBlock>💬 Comment</CodeBlock>를 라벨로 설정했고 댓글이 달려 이슈가 올라오면 다음과 같이 라벨이 생성됩니다.   

![utterances repository](/images/post_250830/config_label_example.png)


Theme 설정은 댓글 박스의 색상 테마를 정하는 옵션입니다. 방문자의 브라우저 설정에 따라 자동 전환되기를 원한다면 또는 블로그 다크모드 지원 여부에 따라 전환되기를 원한다면
<CodeBlock>preferred-color-scheme</CodeBlock>으로 지정하면 됩니다.

## 📎 프로젝트에 Utterances 적용하기
필자의 블로그는 Next.js App router를 사용했고 포스팅은 MDX를 사용해 개발되었습니다. MDX content 영역은 서버 컴포넌트로 사용되기 때문에
댓글 영역은 클라이언트 컴포넌트로 따로 생성했습니다.
```tsx
// components/Utterances.ts
"use client";

import { useEffect, useRef } from "react";

export default function Utterances() {
  const containerRef = useRef<HTMLDivElement>(null);

  useEffect(function initializeUtterances() {
    const element = containerRef.current;
    if (!element) return;
    if (element.childNodes.length > 0) return; // StrictMode 중복주입 방지

    const script = document.createElement("script");
    script.src = "https://utteranc.es/client.js";
    script.async = true;
    script.crossOrigin = "anonymous";

    script.setAttribute("repo", "grxxn/grxxn_blog");
    script.setAttribute("issue-term", "url");
    script.setAttribute("label", "💬 Comment");
    script.setAttribute("theme", "preferred-color-scheme");

    element.appendChild(script);
  }, []);

  return <div ref={containerRef} />;
}
```
### 🔍 사용법
```tsx
import Utterances from "@/components/Utterances";

export default function BlogPostPage() {
  return (
    <div className="prose mx-auto">
```

### 🪏 에러 발생
Utterances를 붙인 뒤 다음과 같은 에러가 발생했습니다.   

<Callout type="error">
NoModificationAllowedError: Failed to execute 'insertAdjacentHTML' on 'Element': The element has no parent.
</Callout>

App Router는 서버 컴포넌트 기반이라 초기 렌더링이 서버에서 일어납니다.
하지만 Utteracnes는 DOM에 직접 스크립트를 삽입하는 방식으로 동작합니다. 이때 문제가 발생하는 이유는 두 가지 입니다.
1. DOM이 아직 attach되지 않은 시점에 스크립트를 삽입하려고 할 때
2. Strict mode 때문에 개발환경에서 컴포넌트가 마운트 -> 언마운트 -> 다시 마운트 되는 과정이 두 번 실행되면서 중복으로 삽입을 시도했을 때   

이런 경우 Utterances 스크립트가 한 번만 안전하게 주입되도록 가드를 두면 해결할 수 있습니다. 스크립트가 이미 삽입된 상태라면 다시 삽입되지 않도록 다음처럼 조건문을 추가했습니다.
